## Rendering and security implications

The Next.js [data security guide](https://nextjs.org/docs/app/guides/data-security) treats exported Server Actions as externally reachable operations. Every action therefore calls the same authorized application service as a Route Handler. A server-only import guard prevents accidental bundling of the data access layer. Explicit DTOs limit fields returned to browsers.

The [CSP guide](https://nextjs.org/docs/app/guides/content-security-policy) documents that per-request nonces require dynamic rendering and conflict with a static prerendered shell. Proposed decision: dynamic authenticated layouts, a fresh nonce per response, no shared cache for private payloads, and no production unsafe-eval or blanket unsafe-inline. Keep CSS class based; audit libraries that inject styles at runtime. Test actual production responses, including errors and redirects.

Better Auth's [Next.js integration](https://better-auth.com/docs/integrations/next), [2FA plugin](https://better-auth.com/docs/plugins/2fa) and [options](https://better-auth.com/docs/reference/options) inform the session design. Configure an explicit trusted base URL, database-backed revocable sessions, trusted origins and supported cookies. Require MFA for privileged administrative operations; test the state between password verification and completed MFA. Verify the selected plugin's trusted-device behavior before allowing it for administrators.

## Additional technology decisions

- **Animation:** native CSS transitions first. Motion is not yet a dependency. Browser View Transitions may progressively enhance navigation after compatibility review; navigation must work without them. React experimental APIs are excluded.
- **Font:** [Inter](https://rsms.me/inter/) is a proposed self-hosted interface typeface. Pin the licensed asset release when acquiring it; this report does not include font binaries.
- **Uploads:** private S3-compatible storage is an architectural interface, not a selected vendor or SDK. Require quarantine and a scanner/image processor that can run outside the web request's resource budget.
- **Spreadsheets:** ExcelJS was considered through its [official repository](https://github.com/exceljs/exceljs), but retrieved content was insufficient for a dependency decision. Do not treat it as approved. Compare a maintained XLSX reader and CSV parser against formula behavior, compressed expansion limits, streaming, licensing and security advisories.
- **Queues:** begin with a PostgreSQL job/outbox table and a bounded job runner from the same codebase. This avoids requiring a separate queue service in v1.0. A worker process is a deployment role of the modular monolith, not an independently owned microservice.
- **Messages:** periodic polling with visibility-aware backoff is the proposed v1.0 behavior. Add real-time infrastructure only if a measured operational requirement justifies it.

## Alternatives evaluated

| Approach                                 | Benefit                                                                                    | Cost / decision                                                                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| Node Next.js monolith + PostgreSQL       | Closest match to the brief; one authorization/service boundary; server-side upload tooling | Recommended; needs Node-capable hosting and operational services                                                                 |
| Worker application + external PostgreSQL | Potential proximity to users                                                               | Requires adapter, connection, memory, authentication and job-processing validation; not selected merely because a starter exists |
| SPA + standalone API                     | Clear independent clients                                                                  | Two deployment/build surfaces and duplicated integration work; unnecessary for v1.0                                              |

## Pre-implementation research gate

Finish unresolved migration and dependency reviews listed in README. Record engines, peer requirements, licenses and security advisories for every added major dependency. Then generate exact pins and a lockfile, run a compatibility smoke build, and update this document with evidence. Do not describe an untested selection as production-verified.
